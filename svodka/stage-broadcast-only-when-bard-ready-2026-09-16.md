# Stage broadcast starts only when Bard Kai is ready

## Симптом
- Текст историй на сцене запускался, когда самого барда еще не было на месте.

## Причина
- `advance()` мог стартовать по локальному таймеру до подтвержденной готовности `stage_bard`.
- Проверка "готовности шоу" была слишком мягкой и не гарантировала:
  - наличие `stage_bard` в server schedule;
  - `atSeat=true` именно для барда;
  - физическое нахождение спрайта Кая у сценической точки.

## Исправление
- Файл: `apps/client/src/sprites/haven-stage.ts`.
- Добавлен guard `canRunPerformance()`:
  - требует актуальный server schedule;
  - требует `stage_bard.atSeat && !asleep`;
  - требует, чтобы спрайт Кая был видим и находился рядом с `seat` (<= 18px);
  - требует `atSeat` для всех участников текущего roster.
- Изменения поведения:
  - `performancePaused` стартует как `true`;
  - удален безусловный локальный `schedule(600, advance)` на старте;
  - `resumePerformance()` разрешается только через `canRunPerformance()`;
  - `advance()` теперь повторно проверяет guard и мгновенно ставит паузу, если готовность пропала.

## Результат
- Истории больше не идут "без вещателя".
- Вещание стартует только когда Кай реально на сцене и подтвержден server state.
